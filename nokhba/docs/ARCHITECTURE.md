# Nokhba Learn — architecture & conventions

Nokhba (نخبة) is an AI-powered learning platform: Next.js 16 (App Router, Turbopack), TypeScript, Tailwind v4 + shadcn/ui (Radix), Framer Motion, Prisma 6 on PostgreSQL, Auth.js v5, Zod, Recharts, an AI orchestration layer with a provider abstraction, and RAG over approved course content.

## Layout

```
app/                    routes (App Router)
  (public)/             marketing + catalog browsing without sign-in (layout: header/footer)
  (auth)/               sign-in, sign-up, forgot/reset password, verify-email, onboarding
  (platform)/           signed-in app (layout: glass nav rail / bottom nav / command palette / AI orb)
  api/                  route handlers (REST-ish JSON; SSE for AI chat)
ai/                     AI layer — orchestrator, context builder, prompts, gateway, providers, rag, memory, schemas
components/             ui/ (shadcn + glass primitives), layout/, ai/, command/, course/, feature folders
config/                 site.ts (name, categories, enums) · nav.ts (route registry)
hooks/                  client hooks (use-ai-chat)
lib/                    db, i18n, auth (permissions/session), security (rate-limit, validate, audit), content (lesson blocks), utils, api client
messages/{en,ar}/*.json i18n dictionaries — one file per feature, merged automatically
prisma/                 schema.prisma, migrations, seed.ts + seed-data/
server/services/        business logic (progress, skills, recommendations, notifications, achievements, certificates, analytics-events)
scripts/                browse.cjs (Playwright page checker)
types/                  ambient types (next-auth)
docs/                   this file + feature notes
```

## Request flow

UI (server components fetch via services; client components call `/api/*` with `lib/api.ts`) → route handler / server action (`requireUserApi`, `requirePermissionApi`, zod `parseBody`, `rateLimit`) → `server/services/*` → Prisma. AI: UI → `/api/ai/*` → `ai/orchestrator` → `ai/context/builder` (user/course/lesson/RAG) → `ai/prompts/templates` → `ai/gateway` → provider. UI never touches providers.

## Conventions every feature follows

- **Server components by default.** Fetch with services/Prisma in `page.tsx`; pass plain data to `"use client"` components. Route params are async: `const { id } = await params;` with `PageProps<"/route">` / `LayoutProps<"/route">` (globals generated by `next typegen`).
- **Auth**: pages `await requireUser()` / `await requirePermission("course.publish")`; APIs `await requireUserApi()` / `requirePermissionApi(...)` inside `apiHandler(async (req) => …)`. Check ownership on every mutation (user can only touch their own rows). Never trust ids from the client for authorization.
- **Permissions** live in `lib/auth/permissions.ts` (`can(subjectOf(user), "x.y")`). Roles: LEARNER, INSTRUCTOR, COURSE_MANAGER, ORG_MANAGER, ADMIN, SUPER_ADMIN; org members may be MEMBER/MANAGER/OWNER.
- **i18n**: server `const { t, locale } = await getI18n()`; client `const { t, locale } = useI18n()` / `useT()`; localized fields via `pick(record, "title", locale)` (server) or `useLocalized()(record, "title")` (client). Keys are `"<file>.<path>"`, e.g. `messages/en/dashboard.json` `{ "todayPlan": { "title": "…" } }` → `t("dashboard.todayPlan.title")`. **Every string the user sees goes through t() and exists in BOTH en and ar files.** Numbers/dates via `lib/i18n/format.ts`. Use logical CSS (`ps-`, `pe-`, `start-`, `end-`, `ms-auto`) — never `left/right/pl/pr`. Icons that imply direction get `rtl:-scale-x-100`.
- **Design system**: tokens in `app/globals.css`. Surfaces: `<Glass level={1|2|3|4}>` (nav / cards / modals & AI / focused learning) or classes `glass-1..4`, `glass-interactive`, `glass-edge`. Page scaffold: `<PageContainer>` + `<PageHeader eyebrow title description actions>`. Empty/error: `components/ui/empty-state.tsx`. Course cards: `components/course/course-card.tsx`. Typography: `text-display`, `text-title`, `font-heading`; numbers `tnum`. Buttons: shadcn `Button` (variants default/outline/secondary/ghost/destructive/link; sizes xs/sm/default/lg/icon*). Toasts: `import { toast } from "sonner"`. Motion: framer-motion, subtle, respects reduced motion (MotionConfig is global). Light + dark + system via `next-themes` (`dark:` variants; prefer tokens).
- **Responsive**: desktop rail, mobile bottom nav (already in the shell). Pages use `container-app`, grids that collapse to one column, `pb` handled by the shell. Design dedicated mobile interactions where needed (sheets, bottom actions).
- **Lesson content** = JSON blocks (`lib/content/lesson.ts`: text/video/image/diagram/code/knowledge_check/activity/file/interactive). Use `parseLessonContent()`; render markdown with `react-markdown` + `remark-gfm` in `.prose-lesson`.
- **AI**: conversational → `useAiChat({kind})` + `<ChatThread>`/`<ChatComposer>` (POST `/api/ai/chat`, kinds tutor|companion|code_help|search). One-shot → POST `/api/ai/generate` (quiz, flashcards, summary, study_plan, notes_tool). New structured needs → add an action in `ai/prompts/templates.ts` + zod schema in `ai/schemas.ts` + a branch in `ai/providers/local-demo.ts` so demo mode still works, then call `orchestrator.structured(...)` from your route. Never call providers directly.
- **Analytics**: `track(userId, "event_name", props)` from `server/services/analytics-events.ts`. **Audit** privileged actions with `audit(actorId, "course.published", {type, id}, details)`.
- **Validation**: zod on every API body (`parseBody`), `parseQuery` for search params, `validateUpload` for files.
- **Files**: uploads are stored under `storage/` (gitignored) via `lib/storage.ts` if present; otherwise store metadata only and keep the architecture ready.
- **Schema is frozen for feature work.** Use existing models/JSON fields. If something is truly missing, note it in your report; do not run migrations.
- **No new npm dependencies** without noting it in your report. Available: react-hook-form + @hookform/resolvers, zod, framer-motion, recharts, cmdk, sonner, lucide-react, date-fns, qrcode, nanoid, react-markdown/remark-gfm, @uiw/react-codemirror (+ python/javascript langs, one-dark theme), @dnd-kit/*, all Radix packages via shadcn components in `components/ui`.
- **Accessibility**: semantic HTML, labels on inputs, `aria-label` on icon buttons, visible focus (global), keyboard operable dialogs/menus (Radix), `prefers-reduced-motion` respected.
